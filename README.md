## ★ 相比 V2.0.5 更新了什么

V2.0.5 的基线是 device `v1.3.329` + player `pl-1.6.148`；
V2.0.6 的基线是 device `v1.3.359` + player `pl-1.6.163`。

这一版的主线是**播放记录与进度**：把「谁在放、放到哪、换台设备还能不能接上」这条链做实。
在此之上补了语音读时长/跳转、合集子书点名播、续播的本地/缓存/在线三级查找。

### 一、播放记录 / 进度上报（本版主线）

| # | 能力 | 说明 |
|---|---|---|
| 1 | 暂停立即结算 | 网页暂停/停止、实体键暂停、语音 stop、设备关机**四条路**都立刻结算上报，不再等下一拍（v1.3.340 / pl-1.6.156） |
| 2 | 位置同步带设备身份 | `/v1/pos` 上报、拉流 URL 都带 `dev=`（MAC12）；群晖 docker 下 R1 的记录不再误落「网页」桶（v1.3.342/346） |
| 3 | 起播即上报 | `ProgProgress` 每 2 秒**轻探** player 指纹（曲名\|curId\|playing\|pos>3s），指纹变化或 15 秒到期才真正 tick；不再为一次判断拉整张队列（v1.3.349） |
| 4 | 位置门槛放开 | 起播瞬间 pos 就是 0，原「pos<8 秒不报」会把起播那一拍挡掉；服务端对**带 devId** 的低位置上报放行（v1.3.349） |
| 5 | 入队盖章 | 谁把书排进队列谁写队列项 `album`（书名），device 只读不算 —— 不再靠猜「这是哪本书」（v1.3.350） |
| 6 | 书级共享进度 | 续播先问服务端 `/v1/resume?q=&dev=`（含「听完⇒下一集」），命中就把集号/秒数写回本地；换台设备也能接着听（v1.3.336/347） |
| 7 | 电台判据改 URL 形态 | 电台的 `liveStream`/`qRadio` 在起播瞬间**都是 false**，靠它判会把广播漏报；改成按 URL 形态（`/radio/`、外网直链）判定（v1.3.352） |
| 8 | 上报名统一短名 | 记录里书名与队列/列表显示用同一套短名，避免同一本书两个名字（v1.3.351） |

### 二、听书身份唯一化（v1.3.348）

| # | 变化 |
|---|---|
| 1 | **合集子书的书身份 = 子书名**（「黑暗森林Ⅱ」「死神永生Ⅲ」），合集名（「三体」）只作 `series` 展示位 |
| 2 | 记录里**不带父名前缀** —— 否则三部曲会被记成同一本、进度互相覆盖 |
| 3 | 禁止用全局「上一本书」兜底：认不出书名就**不上报**，宁缺毋滥（这是「本地书被记成上一本在线书」的根因） |
| 4 | 服务端不再拿 stream 记录反推集号（预载下一首也带 `live=1`，会把第 1 集改成第 2 集） |

### 三、合集（coll）语音点播（v1.3.353~357）

| # | 变化 |
|---|---|
| 1 | `ablFind` 不再一票跳过合集目录，合集本身可播 |
| 2 | **指名播**：说「黑暗森林」就播那一部，不再总是落回合集第一个子书 |
| 3 | 合集子书按子书名找本地文件与续播记忆，与单本同一套逻辑 |

### 四、语音读时长 / 快进后退 / 跳到第几秒（v1.3.358）

| # | 变化 |
|---|---|
| 1 | 新 MCP 工具 `self.r1player.seek_play`（第 37 个工具），语义与 stem 固件 `self.stem.seek_play` 一致 |
| 2 | `sec` = 绝对秒（「跳到第 12 分钟」⇒ 720）；`delta` = 相对秒（「快进 30 秒」⇒ 30，「后退 2 分钟」⇒ -120）；**都不传 = 只查进度** |
| 3 | `status` 末尾追加「已播到 X，共 Y，还剩 Z」；有书名时报「《书名》第 N 集」 |
| 4 | 直播流一律拒绝：判据是 **`durMs<=0`**（电台的 `liveStream` 起播瞬间是 false，不能靠它）；越界钳到 `dur-2` 秒，避免拖到片尾直接跳下一集 |
| 5 | 网页同入口：`/api/act?op=progress`、`op=seek_play&sec=NNN`、`&delta=-60` |

### 五、续播查找顺序：本地库 → 缓存 → 在线（v1.3.359）

| # | 变化 |
|---|---|
| 1 | 本地库同名书可能只是**残卷**（实测 `/audiobook` 里《凡人修仙传》只剩 3 集，在线版 2113 集），而 `ab_loader_album` 会一直指着它 |
| 2 | 本地集表里找不到目标集时，自动退 `/api/ab/episodes?q=&ep=`（服务端内部是 `ab_cache.json` 永久缓存优先、未命中才回源 = 缓存+在线两级） |
| 3 | 再找不到（换了短版本）⇒ 退到 ≤目标集的最近一集，话术改成「这版没有第 N 集（共 M 集）—— 从第 K 集继续」，不再回「找不到可播的那一集」（小智会把它转述成「找不到上次播放的记录」） |
| 4 | 降级成功后把 loader 纠正成在线 albumId，下次不再踩同一个坑 |

### 六、缺集救援 / 脏缓存（v1.3.332~335）

| # | 变化 |
|---|---|
| 1 | 按需单点（带 `ep=N`）时把集号透传给服务端，缺集占位播到才有机会被救援回来 |
| 2 | 历史「错误缓存」里的脏占位行（带假 rid）强制重问服务端一次 |
| 3 | 补书名改用**短书名**（全名太长，列表里看不到集号） |
| 4 | 歌曲解析服务端优先（吃 `/api/song/resolve` 的 rid 缓存），减少一次上游搜索 |

### 七、网页控制台 / player（pl-1.6.149~163）

| # | 变化 |
|---|---|
| 1 | 暂停/停止/实体键暂停 ⇒ 立即通知 device 结算上报（pl-1.6.156） |
| 2 | **手动暂停不被小智自动恢复**：网页/实体键显式暂停后，小智说完话不会自作主张续播；显式起播/切歌才清标记（pl-1.6.157） |
| 3 | 按钮延时根治：`WebSrv` 改成**每连接一线程**，不再串行 accept（pl-1.6.157） |
| 4 | 缺集按需救援：新增 `/api/abep`（点缺集时按需救）、`/api/abrev`（按服务端 `rev` 复查集表），占位行与服务端同口径（pl-1.6.151/152） |
| 5 | 队列项自带书名（pl-1.6.162）：播什么书由入队方盖章，player 不再猜 |
| 6 | 续播口径统一 10 秒（pl-1.6.154/158），文案同步改 |
| 7 | **转码流伪 VOD**（pl-1.6.163）：服务端降档转码的流带时长、可拖动，播放页出青色「转码」pill |
| 8 | 蓝牙灯收口到设备灯效服务（pl-1.6.150） |

### 八、「退下」本地兜底（v1.3.330）

云端不一定把「退下」映射到 MCP 工具；本地对高置信度短语直接退出 LISTENING，保证真的闭嘴。

### 九、已知遗留（不影响日常使用）

| 项 | 说明 |
|---|---|
| 播放列表不持久 | 设备重启 / 重装任何一个包，播放进程一起重启 ⇒ 播放列表清空，重新点一次「导入播放列表并播放」即可 |
| 红标是内存态 | 「没配上」是 player 的会话内判定，player 重启后全部消失。**重启后不红了 ≠ 修好了** |
| 自动匹配仍可能配到翻唱 | NAS 搜索按热度排序，用**长按歌名 → 重链接**兜底 |
| 本地库残卷 | 同名书本地只剩几集时会先按本地播（本地优先），集号超范围才降级到在线；想直接听完整版可说在线版主播名或先清掉本地目录 |
| 书名号套娃 | 本地书的 name 自带书名号时，语音回话会出现「《《庆余年》有声小说》」（能播，只是文案难看） |
| 随机闹钟只吃在线池 | 断网时随机响铃可能放不出声（指定铃声有缓存，不受影响） |
| 长按 / 三击未接管 | 仍是原厂的 WiFi 配网 / 蓝牙配对 |

## 构建

```bash
cd 04-build-scripts/device   && bash build_rel_V206.sh    # → XiaoZhi_Unisound_V2.0.6.apk
cd 04-build-scripts/player   && bash build_rel_V206.sh    # → XiaoZhi_EchoService_V2.0.6.apk
```

发布脚本是**生成**出来的（`_gen_rel_v206.py` 读日常脚本改名、并在 javac 前临时把版本串
改成 `2.0.6` / `pl-2.0.6`，构建完立刻还原）；源码树永远停在测试序列
（`XzBootstrap.VERSION = 1.3.359`、`Boot.VER = pl-1.6.163`），两条线不会串。
工具链放 `04-build-scripts/tools/`（或 `R1_TOOLS=<目录>`），详见 `04-build-scripts/环境说明.md`。

## 安装 / 升级

1. 音箱固件必须是 **3448**，与电脑同一网络、已开 adb 网络调试。
2. 装两个包（覆盖安装，收藏、闹钟、「我的节目」与设置都保留）：
   `XiaoZhi_Unisound_V2.0.6.apk` → `com.phicomm.speaker.device`；
   `XiaoZhi_EchoService_V2.0.6.apk` → `com.phicomm.speaker.player`；
   首次装还需 `XiaoZhi_SoHost_V2.0.1.apk`（Opus so 只能由系统安装器解出）。
3. 浏览器打开 `http://<音箱IP>:8080/` → 顶部「激活」卡片取 6 位激活码 → 到小智服务端绑定。

**升级提示**

- 装完 device 包，播放列表会清空（见「已知遗留」），收藏、闹钟、「我的节目」不受影响。
- 从 V2.0.4 及更早升级，浏览器可能还压着旧页面（旧版给了 10 分钟强缓存）：
  等顶部「页面已过时」横幅出现点一下，或手动刷新一次。
- 本地有声书库要服务端 ≥ v1.2.1（`/api/abl/*`）；V2.0.6 的续播降级、书级共享进度建议配
  MyXiaoZhi_MediaServer ≥ V1.7.55。
